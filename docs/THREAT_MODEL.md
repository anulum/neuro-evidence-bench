# Tooling trust boundaries

The current assets are maintained source, exact descriptor/schema/lock identities and truthful infrastructure reports. Maintainer-reviewed executable policy and its independently pinned schema are trusted. Received JSON values are data; they cannot select an executable, plugin, repository identity or weaker policy.

The input boundary refuses duplicate keys, nonfinite numbers, invalid UTF-8, unpaired surrogates, oversized, linked and nonregular input. Fixed authored diagnostics avoid echoing confidential values. Unknown input and unavailable dependencies cannot pass. Generation requires accepted metadata and exclusively creates a new caller-chosen relative output; verification never replaces the canonical inventory.

The tooling assumes a stable ordinary local filesystem and reviewed environment. It does not sandbox hostile concurrent filesystem changes, operating-system compromise or power loss. Static checks do not prove metric correctness, raw-population completeness, measured origin, metrological calibration, comparison fairness or independent reproduction. Those require actual accepted domain sources, instruments and consumers.

Future benchmark inputs must preserve prior policy, every attempted observation, actual operating context and source authority. A valid seal cannot turn an estimate into a measurement, omit a failed trial, supply an absent instrument or make incomparable results comparable.
